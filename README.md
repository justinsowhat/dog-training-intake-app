# PawsitiveMind

An AI-assisted intake and consulting app for **animal behavior training**. An owner
shares a few basics about their animal, has a short, natural conversation with an AI
behavioral consultant, and walks away with a personalized, **force-free** training plan
they can keep iterating on.

It works with any companion animal (dog, cat, or other), uses positive-reinforcement
methodology throughout, and needs **no account** to start — an in-progress consultation
is saved in the browser and survives a restart.

## How it works

```text
Landing → quick intake form → conversational chat → training plan → follow-up chat
```

1. **Intake form** — a short structured profile (name, species, breed, age, main concern).
2. **Chat** — the AI consultant asks one question at a time to understand the behavior.
   The opening quick-reply chips are generated by the LLM from the owner's stated concern.
3. **Plan** — the agent decides when it has enough information and **proposes a structured
   training plan mid-conversation** (via a tool call). There's also a manual "generate now"
   path that skips the questions.
4. **Iterate** — the owner can keep chatting to refine the plan ("make week 1 lighter"),
   and the agent revises it in place.

## Architecture

A two-package monorepo. The browser talks to the FastAPI backend directly (CORS enabled).

```text
dog-training-intake-app/
├── backend/      FastAPI service (Python, uv) — package lives in backend/app/
├── frontend/     React + Vite single-page app (TypeScript)
└── README.md     (this file)
```

- **Backend** — FastAPI + SQLAlchemy (async) over SQLite. All LLM orchestration lives in
  a service layer; the model is called via OpenRouter and must support **tool/function
  calling**. The chat endpoint streams **NDJSON** typed events so the agent can emit
  conversational tokens and a structured plan over one response.
- **Frontend** — React 19 + Vite. A small `fetch`-based hook consumes the NDJSON stream
  (no AI-SDK dependency). Assistant messages render Markdown. Session + chat transcripts
  persist to `localStorage` (anonymous; contact info is collected later, not to start).

### Backend layout

```text
backend/
  pyproject.toml, uv.lock, .env(.example)
  app/
    main.py            FastAPI app  ->  app.main:app
    api/chat.py        /consultation routes
    core/              config, database, deps, ORM models
    schemas/           Pydantic intake + plan schemas
    services/          llm.py (orchestration), prompts.py (prompt templates)
    tests/             pytest suite
```

### Key API endpoints (prefix `/consultation`)

| Method & path | Purpose |
|---|---|
| `POST /start` | Create a consultation from the intake form; returns `consultation_id`. |
| `POST /{id}/suggestions` | LLM-generated opening quick-reply chips (best-effort, falls back gracefully). |
| `POST /{id}/chat` | Streaming chat (`application/x-ndjson`: `token` / `plan` / `message` / `done`). The agent may autonomously propose or revise the plan. |
| `POST /{id}/finalize` | Force-generate the final plan, skipping the questions. |

The backend rebuilds conversation context from its stored history per `consultation_id`,
so a resumed session continues coherently.

## Getting started

Run the two services in separate terminals.

### Backend

```bash
cd backend
uv sync
cp .env.example .env          # set OPENROUTER_API_KEY (and a tool-calling MODEL_SLUG)
uv run uvicorn app.main:app --reload   # http://localhost:8000
```

### Frontend

```bash
cd frontend
npm install
cp .env.local.example .env.local       # VITE_API_BASE (defaults to http://localhost:8000)
npm run dev                            # http://localhost:3000
```

Then open <http://localhost:3000>.

## Testing

```bash
cd backend && uv run pytest            # backend unit + API tests
cd frontend && npm run build           # tsc typecheck + Vite production build
```

## Notes

- **Model must support tool/function calling** — the plan generation and opening
  suggestions rely on it. Set `MODEL_SLUG` in `backend/.env` accordingly.
- **Database** — defaults to a local SQLite file (`backend/pawsitive_mind.db`), created on
  startup. If you change ORM columns, delete it so the schema rebuilds (no migrations yet).
- **No account needed** — consultations are anonymous; the `consultation_id` plus
  `localStorage` is the handle. "Start over" clears local state.

See `backend/README.md` and `frontend/README.md` for package-specific details.
